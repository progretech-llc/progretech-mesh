# CUDA image execution for the first factory soak

Image generation preserves the existing ROCm default. Explicit FACTORY_IMAGE_DEVICE=cuda selects the isolated comfyui-cuda Python environment on NVIDIA RTX5060Ti; FACTORY_IMAGE_DEVICE=rocm selects AMD. The selected interpreter must exist and pass the device probe; there is no automatic backend fallback. Existing ComfyUI code and model paths remain unchanged. Video/music remain their previous routes and are not qualified for CUDA by this change.

Generation requires an owned factory-heavy-command ancestor lease through ~/ptinternal/bin/factory-admission, mounted PT_CONTEXT and an allowed backend. CUDA additionally requires at least11,000MiB free NVIDIA VRAM. An occupied cache is a scheduling condition; do not kill another active task to free it. Coordinate native completion/cache expiry or release only a known idle factory model under the owned lease. The generator fails closed instead of switching silently toCPU/AMD.

Intermediates and generated rasters stay under /mnt/pt-context/job-artifacts/factory-media/<job>. ComfyUI binds loopback and writes into the owned job. The router rejects artifacts outside that job. A graceful SIGINT then bounded termination/kill/reap sequence owns ComfyUI cleanup. The router starts the launcher in an isolated process group and terminates/reaps that owned group on caller timeout; it never signals another factory job. No cloud inference, downloads of new model weights or production publication is performed by this code.
