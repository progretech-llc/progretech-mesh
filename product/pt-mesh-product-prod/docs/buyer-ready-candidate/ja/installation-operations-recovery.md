# Mesh のインストール、運用、復旧

状態: 購入者向けレビューと品質レビュー待ち。ソース基準版: `86dc872d71ec2f668174f632092b371f57cf24c0`。この草案は顧客環境へのインストールを許可するものではありません。この候補では、商用パッケージ、購入者向け対応バージョン、有料アーカイブ、価格、サポート/SLA、ホスト型 SaaS の提供を定めていません。

## インストールの境界

正確なソース版、依存関係、完全性記録、ライセンス、設定プロファイル、ロールバック手順が確認され、通常のリリース審査を通過した将来のパッケージだけを使用してください。この候補には審査済みの購入者向けパッケージはありません。この草案を評価する間は、本番資格情報を使わず、実際のゲートウェイにも接続しないでください。

使い捨てのプライベートホストでソースを隔離して確認する場合、現在のコンテナイメージは Python 3.12 を宣言し、WSGI サーバーとして Gunicorn を起動します。`requirements.txt` はバージョン範囲を指定しています。以下のコマンドは、管理されたレビュー環境の例に限られます。再現可能またはサポート対象の本番インストールにはなりません。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/gunicorn --bind 127.0.0.1:8080 --workers 1 --threads 80 --timeout 0 main:app
```

この隔離レビュー中は loopback のみで待ち受けてください。LAN やインターネットに公開しないでください。実際の秘密情報、顧客の ID 対応表、データベース、ゲートウェイのアドレスを設定しないでください。購入者向け手順にする前に、品質レビューで必要な環境設定と依存関係の正確な固定版を決める必要があります。

Mesh の Flask サーバーとネイティブホストコネクターは、別々の配布先です。`openclaw-plugin-progretech-mesh/`、Office の Node プロバイダー、ホスト用 Python バンドルを維持してください。Flask サーバーをインストールしても、これらのコネクターがインストール済み、または適格であることにはなりません。Dockerfile が Gunicorn ワーカーを 1 つにするのは、WebSocket とセッションの稼働状態がプロセス内にあるためです。共有状態の設計を別途レビューせずに、ワーカーやレプリカを増やさないでください。

## 運用

購入者向けリリースの前に、正確でレビュー済みの設定表が必要です。現在のソースは `MESH_ENVIRONMENT`、`MESH_PUBLIC_ORIGIN`、`MESH_AUTH_MODE`、`MESH_FIREBASE_*`、`MESH_OWNER_UID_BINDINGS`、`MESH_ACCOUNT_STORE`、`MESH_ACCOUNT_DB` などの選択項目を読み取ります。選択項目が存在することは、安全な値やサポート対象の構成を意味しません。値は購入者が管理する承認済み手順でのみ選択してください。秘密情報は購入者のシークレット管理サービス、または保護された実行環境から注入してください。ソース、シェル履歴、チケット、スクリーンショット、ログ、このガイドには記録しないでください。

`mesh_account_store.py` には SQLite と Firestore の実装があります。アプリケーションの既定値は環境によって変わり、テストではメモリを使います。推奨する前に、品質レビューで本番用バックエンドのアクセス制御、耐久性、バックアップ、復元を確認してください。アカウント設定と、プロセス内の接続、ソケット、イベント、転送データは別のものです。サービスを再起動しても、これらの稼働中セッションは復元されません。

このソース基準版の Cloud Run テンプレートは Knative/Google Cloud Run 用です。Cloud Foundry や SAP BTP の適格性を示すものではありません。SAP テナント用コネクターや BTP 配備プロファイルがあるとは主張しません。

## 復旧

1. 変更を止め、正確なパッケージ版、設定スキーマ版、ストレージバックエンド、障害時刻を記録します。インシデント記録に秘密の値を含めないでください。
2. 影響を受けたサービスを隔離します。復旧試験のために実際のゲートウェイを登録または再接続しないでください。
3. 選択済みバックエンド向けのレビュー済み手順を使い、購入者所有のバックアップを別の復旧環境へ復元します。唯一のバックアップを上書きしたり、未検証の設定を稼働中サービスへ戻したりしないでください。
4. 合成 ID を使い、復元されたアカウント設定と所有者境界を確認します。ソケット、稼働中セッション、一時イベント、転送データはプロセス内にあり、バックアップ対象ではないため、失われたものとして扱います。
5. 認証、所有者の分離、コネクター互換性、ロールバックは隔離環境だけで確認します。元のホストのネイティブランタイム、権限、作業、資格情報を維持します。
6. 将来承認されるリリースおよび復旧手順を通してのみサービスを再開します。この草案には、鍵のローテーション、本番ロールバック、購入者サポート窓口のコマンドはありません。

インストールや復旧の際に、元のプロジェクト憲章、ライセンス表示、ロードマップ、コネクター配布物を削除しないでください。正確なパッケージのインストール、設定、永続化、バックアップ/復元、更新/ロールバック、セキュリティ、各言語の文書に関する品質ゲートが通るまで、このガイドは審査待ちです。
