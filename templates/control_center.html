Minimum Requirements

  • A signed-in Mesh owner and a linked, verified agent with a connected gateway.
  • A compatible local control provider with an explicit binding to this agent. Linking alone does not install or authorize workstation controls.
  • Allow profile storage to save settings. Allow inventory to discover this agent’s configured models and role.
  • Voice preview needs a working TTS provider and speaker. Listening needs a microphone and voice service; vision needs a camera or configured visual source.
  • Declare whether this agent lives on a workstation to reveal device controls. Each feature also needs its local capability and permission.

There is no universal GPU or RAM minimum for Mesh controls. Model memory, quantization, context length and media workloads determine hardware needs.

Permissions & data

Profile details and permissions are saved on the agent’s host. Mesh relays requests and responses in memory; it does not store these profiles in the cloud.

Inventory responses expose model names and role metadata. System and device responses expose host resources and device names. Preview text is sent to the host and played on its speaker. Microphone and vision controls affect the configured host source.

Provider credentials stay local. Never enter keys, tokens or passwords in this profile. Browser microphone permission for Mesh chat is separate from workstation listening.

Revoking a grant blocks future requests; it does not stop a service already running. Stop voice before revoking microphone access.
